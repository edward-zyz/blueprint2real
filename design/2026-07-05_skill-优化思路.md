## 二、优化清单

### P0 — 立即（低成本高收益）

1. **B2R_HOME 改运行时解析**（`bootstrap/workflow/scripts/init.mjs`）
   不再把 skillRoot 烘焙进目标项目 package.json；bootstrap/upgrade 时写 `<devRoot>/.b2r-home` 项目本地配置，alias 统一从该文件读；`init.mjs --upgrade` 自动重写。跨机克隆后跑一次 upgrade 即修复。
2. **修 triage 判据语义**（`agents/roadmap-planner.md` + SKILL.md 路由表）
   "满足任一"模糊表格改决策树：先数 `files_estimated.length` → 再看新接口/schema → 再看安全敏感；`reasons[]` 与判据逐项对应；主线收 `0-triage.json` 后加机械校验：`files_estimated.length` 与 level 上限矛盾即打回（不需要 LLM 判断）。
3. **加批次完整性闸**（SKILL.md 质检节点表 + 批次记录）
   泛化既有 `e2e-groups.md` 机制：mint 后无论 e2e 开关都落一行批次记录；每次 handoff 后主线亲跑 `batch:status` 输出"计划 N / Done M / 剩余: [ids]"。给编排者自己设 gate，堵"漏 pi"同款退化。

### P1 — 结构性

4. **诚实重定位 + 能力分层**（SKILL.md 开头新增"自主边界"一节）：集中列全"必停问人"清单；标注每条线环境前置与自给程度——L1-L3 后端循环 = 可无人值守核心；UI / E2E / L0 direct-fix = 需活服务或人工配合的可选枝。
5. **红 gate 校验失败结构**（`receipts-schema.md` + SKILL.md 质检表）：`failing_test_output` 从"非空"升级为"必须含失败证据结构"（非 0 退出码或 FAIL/Error 关键字）；更彻底：红阶段输出落盘 artifact，主线 grep 文件而非信 receipt 字段（与 O16"主线亲 grep tbd"同构）。
6. **堵 L1 自评漏洞**（`plan-drafter.md` + 主线 gate）：最低限度把 `l1_self_review_verdict` 存在性 + 枚举值校验做成主线硬检（缺字段 = 交付失败重派）；若小工单轻量化后成本可接受，取消自评旁路走轻量独立 reviewer。
7. **编号统一 + 契约单源**（SKILL.md / `quality-gates.md` / `pipeline-flow.md`）：Gate 号统一为 `Gate@Stage` 命名，消除 Gate4/Gate6 冲突；声明 quality-gates.md 为唯一权威，pipeline-flow.md 降级为图示。
8. **修 validate-state 鸡生蛋**（`validate-state.mjs` + `handoff-committer.md`）：5-handoff.json 允许 `hash:"pending"` 中间态（validate-state 降 warn），`verify:handoff` 终检才要求真 hash。
9. **lint:redlines 空跑去形式化**：未配红线时 Stage 4 gate 显示 `SKIPPED(未配置)` 而非通过；Stage 1 播报行加"红线:未配置"。

### P2 — 架构债

10. **skill 可用性探测前移**（SKILL.md 启动协议 + 全部 agent 模板）：主线启动时探测一次，结果以 `{{skillsAvailable}}` 注入派工 prompt；模板只留一套路径。
11. **小产物轻量路径**：triage 新增 DOC/SPIKE 档（产物仅 .md、不触运行代码）：spec+plan+impl 合并单 agent，跳过 regression 与 arch review。
12. **receipt schema 瘦身**（`receipts-schema.md` 407 行）：每 stage 主线 gate 真正读的字段（~10 个）标 REQUIRED，其余 OPTIONAL；宽松解析，必填齐即放行。
13. **SKILL.md 减脂**：事故叙事移 references/CHANGELOG，正文只留规则与理由，预计减 1/3 体积。

## 三、对报告 P1"停止全自主宣称"的保留意见

建议**重定位而非降级**：L1-L3 后端主循环在 11 工单实战里确实无人值守跑通，是真实且稀缺能力；正确表述是"核心循环无人值守 + 边界决策 human-in-the-loop"，分界线写死在文档里（见第 4 条）。

## 四、落地节奏与结果（2026-07-05 更新）

- **迭代 1（已完成）**：P0 三项落地（bootstrap v5.6.0）+ 3 用例 × 新旧对比评估。结果：新 skill 断言 15/15（100%），旧 skill 13/19（70%），时间/token 持平；区分点全部落在 P0-1/P0-2/P0-3 对应的机械断言上。评测代理另发现两个新缺口：`--bootstrap` 不写 `.b2r-version`、生成配置硬编码 legacy `cd dev`。
- **迭代 2（已完成）**：修上述两缺口（模板引入 `{{devRootName}}`、bootstrap 补写 `.b2r-version`）+ P1 三项纯文档改动（4 自主边界一节 / 5 红 gate 失败结构 / 7 Gate4-Gate6 冲突消除 + quality-gates 单源声明）。复核代理确认：新项目 bootstrap 一次到位、契约自检零补跑、产物无 legacy 路径。工作流测试 155/155 绿。
- **Description 触发优化（已做，结论诚实记录）**：搭了 20 条触发评估集（10 正 10 负，train/test 6:4）并跑通官方 `run_eval` 管线（期间修了三个测量坑：后台双层包装、真 skill 全局注册遮蔽探针、检测器"首个工具调用必须是 Skill"对编排器类 skill 误判）。但受控实验表明 `claude -p` 探针指标对本 skill 恒为 0——即便在带真实工单状态的仓库里，模型也倾向直接动手而不调 skill（skill-creator 文档自述的 undertrigger 现象），指标不敏感则自动优化循环无意义，遂停止。改为人工把 v5.6 新场景补进 description 触发短语（批次收官 / 续跑中断批次 / bootstrap 新项目 / 换机修底盘）。评估资产保留在 workspace（trigger-eval-v2.json + run_eval_patched.py），将来换测量方式（如真实会话遥测）可复用。
- **迭代 3 候选（未做）**：P1-6 L1 自评硬检、P1-8 validate-state 鸡生蛋、P1-9 lint:redlines SKIPPED 语义；P2 全部（skill 探测前移 / DOC-SPIKE 轻量档 / receipt 瘦身 / SKILL.md 减脂——当前 468 行，逼近 500 上限）。
